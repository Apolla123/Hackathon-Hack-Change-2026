# МТС Energytool: ИИ-консультант для сайта

Чат-бот, который ведёт посетителя от описания проблемы до заявки менеджеру: понимает задачу, задаёт уточняющие вопросы,
подбирает решение **только по базе знаний Energytool**, объясняет простым языком, собирает ФИО, телефон и компанию и
формирует резюме диалога.

## Быстрый старт (одна команда)
```bash
cp .env.example .env        # впишите LLM_API_URL и LLM_API_KEY от организаторов
# положите материалы кейса в data/kb/ (см. data/kb/README.md)
docker compose up --build
```
Откройте http://localhost:8000. Без Docker: `python main.py` (нужен только Python 3.10+ и `pip install -r requirements.txt`).

## Основной сценарий проверки
1. Включите «Режим отладки» (вверху справа).
2. Напишите: «Выросли счета за электричество в магазине». Бот задаст один уточняющий вопрос или предложит решение. Под ответом видны время ответа и документы базы знаний (✔ использован / найден).
3. Продолжите диалог, вернитесь к прошлой теме: контекст сохраняется внутри сессии.
4. Спросите то, чего нет в базе (цена, которой нет в документах) или постороннюю тему: бот честно скажет, что не знает, и предложит специалиста.
5. Согласитесь на связь с менеджером, назовите ФИО, телефон и компанию: появится заявка с резюме (панель справа, `GET /api/leads`).
6. «Новый диалог» полностью сбрасывает контекст. Старые сессии (в том числе без заявки) остаются в панели «Сессии» и в `GET /api/sessions`.

## Архитектура
```
браузер (static/index.html, виджет static/widget.js)
   │  POST /api/chat
   ▼
app/server.py ── потоки, блокировка на сессию, лимиты ввода
   ▼
app/consultant.py ── 1) запрос для поиска = реплика (+ прошлый вопрос, если реплика короткая)
   │                 2) app/kb.py: BM25 (+ эмбеддинги bge-m3, если есть индекс) → top-K фрагментов + уверенность
   │                 3) ОДИН вызов LLM (app/llm.py): история сессии + контекст + состояние заявки → JSON
   │                 4) проверки: числа из ответа должны быть в базе знаний, иначе один раз переписываем;
   │                    ФИО/компания принимаются, только если клиент сам их написал; телефон — регулярка
   │                 5) конечный автомат заявки none → offered → collecting → done
   ▼
app/store.py (SQLite): сессии, сообщения с debug-данными, заявки
```

**Почему так:**
- **Скорость.** Один ход = один запрос к модели; поиск локальный (миллисекунды); резюме заявки доуточняется моделью в фоне (клиент сразу получает подтверждение, а менеджер видит шаблонное резюме, которое затем заменяется на ИИ-версию).
- **Стабильность.** Если модель недоступна, бот отвечает текстом из базы знаний или честно предлагает специалиста, но не падает. Эмбеддинги необязательны: при их сбое поиск остаётся на BM25.
- **Без выдумок.** Промпт запрещает знания вне контекста; при низкой уверенности поиска (`MIN_CONFIDENCE`) модель получает указание задать уточняющий вопрос или признать отсутствие ответа.
- **Одна зависимость** (`requests`), веб-сервер на стандартной библиотеке: меньше уязвимостей и проще сборка.

## Автоматическая проверка (этап 1)
`solution.py` — точка входа: `python solution.py --input questions.json --output answers.json`. Каждый кейс независим, состояние не хранится.
**Формат входа/выхода угадан**, так как «Технический регламент» не входил в материалы: если он отличается, правятся только `load_cases` и `save_results` в `solution.py`.

## Переменные окружения
См. `.env.example`. Обязательны `LLM_API_URL` и `LLM_API_KEY`. Остальные имеют значения по умолчанию.
Порт: `PORT` (по умолчанию 8000). Внешний сервис: языковая модель Qwen3.8-27B через API организаторов (и `BAAI/bge-m3` для эмбеддингов, если используете индекс).

## Эмбеддинги (необязательно)
`python scripts/build_index.py` считает векторы фрагментов в `data/index/embeddings.json`; готовый индекс можно включить в решение.
В рантайме запрашивается только эмбеддинг вопроса (таймаут 4 с, при ошибке — BM25). Реранкер не используется.

## Встраивание в сайт Energytool и передача заявок
- **Виджет:** на страницу достаточно добавить `<script src="https://<домен-сервиса>/static/widget.js" async></script>`: появится кнопка, чат откроется в iframe. Для другого домена задайте `CORS_ORIGIN`.
- **Заявки менеджерам:** хранятся в SQLite и отдаются через `GET /api/leads`; при заданном `LEAD_WEBHOOK_URL` каждая заявка (ФИО, телефон, компания, резюме) отправляется POST-запросом JSON в CRM или почтовый шлюз. По условию кейса реальные интеграции не требуются, это точка расширения.
- Для продакшена: HTTPS на реверс-прокси, закрыть `/api/sessions` и `/api/leads` авторизацией (в прототипе они открыты для проверки жюри).

## Тесты
`python -m unittest discover -s tests -t .` — 18 тестов без сети и ключей (модель подменяется заглушкой): поиск, телефон, диалог, заявка, изоляция сессий, запасной режим, HTTP.

## Известные ограничения
**!** - **Базы знаний в проекте нет** (данные кейса нельзя публиковать): без файлов в `data/kb/` бот будет предлагать специалиста на любой вопрос. Тестовая демо-база есть только в `tests/fixtures`.
- Поиск без эмбеддингов лексический (BM25 с упрощённым стеммером): синонимы без общих слов могут не находиться.
- Работа с реальной моделью Qwen3.8-27B и сквозной сценарий с ней не проверялись (нет ключа): проверено на заглушке модели.
- История и заявки без авторизации и без шифрования; персональные данные только тестовые.
- Резюме и ответы бота не отправляются во внешние системы, пока не задан `LEAD_WEBHOOK_URL`.
